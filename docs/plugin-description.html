Your Obsidian vault, right inside PyCharm, GoLand and other JetBrains IDEs. Link code to notes with [[wiki-links]], jump to a note with one click, search and browse your notes without switching windows. Obsidian itself does not need to be running: the plugin reads the .md files directly.

Quick start (1 minute)

  1. Open Settings → Tools → Vault Bridge (or click Vault: not set in the status bar at the bottom).
  2. In Vault folder, choose your vault — the folder that contains .obsidian/. Click OK.
  3. The status bar shows Vault: <name> · N notes. Done.

Try it: in any code comment type [[ and pick a note:

# how the retry policy works: [[Retry policy]]
// see [[Traefik#Middlewares]]

A vault icon appears in the gutter — click it, or Cmd/Ctrl+Click the link, to open the note.

The vault is set per project, so different projects can use different vaults. The vault can live anywhere on disk; it does not have to be inside the project.

What you can do

Links in code

  • Completion — type [[ in a comment, string, Markdown or text file to get note names and aliases. If the list does not pop up (some languages block it in comments), press Ctrl+Space.
  • Headings — type # after the note name: [[Note# lists all its headings, [[Note## only level-2, [[Note### only level-3. The link is inserted Obsidian-style: [[Note#Installation]]. [[# lists headings of the current note.
  • Open a note — Cmd/Ctrl+Click or Cmd/Ctrl+B on [[Note]]; [[Note#Heading]] opens at that heading.
  • Gutter icon — on comments with links; several links in one comment show a chooser.
  • Missing notes — links to notes that do not exist are highlighted. Press Alt+Enter → Create note to create it. [[Note#Heading]] is also highlighted when the note has no such heading.

Notes

All actions are under Tools → Vault Bridge, or press Shift Shift and type the action name.

  • Search Vault… — by title, alias, #tag, folder or text inside notes.
  • Open Daily Note — today's note, using the folder, date format and template from Obsidian's Daily notes settings.
  • New Note… — use / for subfolders: ideas/caching.
  • Vault Diagnostics — broken links, duplicate note names, notes that failed to load.
  • Check Note Links in Project — goes through the project's comments, strings, Markdown and text files and lists [[links]] whose note or #heading no longer exists. Double-click a row to jump to it.
  • Re-index Vault — rarely needed: changes, including those made in Obsidian, are picked up automatically.

Tool windows

Open them from View → Tool Windows:

  • Vault Backlinks — which notes link to the open note, with the line around each link; plus its outgoing links.
  • Vault Tags — nested tags (project/alpha) with note counts; start typing to filter.
  • Vault Graph — links around the current note (depth 1–3) or the whole vault. Scroll to zoom, drag to pan, click to open.

Tips

  • Shortcuts are not assigned by default so they do not clash with your IDE. Add your own in Settings → Keymap, search for “Vault”.
  • Turn the gutter icon off in Settings → Tools → Vault Bridge if you prefer a clean gutter.
  • The vault path is stored in the project's workspace.xml, so it is not committed to git.

Something is wrong?

  • “0 notes” — check that the folder is the vault root (the one with .obsidian/), then run Re-index Vault.
  • A link is highlighted as missing but the note exists — the link uses the file name, not the title; check the spelling or add the title to aliases in the note's front matter.
  • “Vault: missing” in red — the vault folder is gone (moved, renamed, unmounted drive). Hover it to see the path, then fix it in Settings → Tools → Vault Bridge or in .vaultbridge.json.
  • Vault Diagnostics shows what was indexed and what was not.
